# StartLine 网球执裁台

面向平板、手机和电脑的网球模拟执裁工具。网页由 GitHub Pages 托管，可直接打开：

**https://hej014519-web.github.io/tennis-umpire/**

使用者无需登录。支持单打／双打、逐分计分、发球提示、双打队内点击换位、自动／手动换边、平面俯视球场、旋转视角、暂停、撤销、判罚确认及比赛记录导出。使用的是可配置的模拟赛制，正式比赛应先核对主办方批准的规则。

## 简洁裁判工作台

默认入口和执裁模式以裁判操作为主：比赛、球场、用时、状态和撤销、暂停等操作组成上方操作栏，下方计分栏将双方比分集中在中间，两侧放大“得分”按钮；开赛前提供“确认赛制并开赛”。正式判罚入口显示已有次数。历史记录、纠错、比赛管理、分享、导出和可选浏览器全屏放在“更多”中。

球场占用其余主要空间，不显示“固定站位示意”、尺寸等说明性标注。选手使用通用头像占位并配合清晰的大字姓名，未提供或使用真实选手照片。工作台填满页面或 iframe 提供的可用区域，球场外的控件随可用视口的横竖比例自动重排，无需手动切换布局。手机、平板和电脑上的球场始终保持横向，两队分处左右半场；设备竖屏时也保持这一方向，并自适应可用宽度。已有观赛链接及只读权限继续兼容。

球场固定采用横向的平面俯视，用柔和的绿色层次、细网线与轻微卡片阴影增加少量层次感，没有倾斜透视、台面厚度或视图切换入口。屏幕转向时自动调整控件排列与场地尺寸，球场保持横向和平面比例。点击“旋转”会将整个场地及场内标记在平面内旋转 180°，头像与姓名保持正向可读。比分、姓名与两侧得分按钮按场上队伍的左 → 右相对位置一起调整。换边或旋转仅调整展示位置，固定的 A／B 球队身份（`SideId`）、已记比分、处罚记录和发球归属保持不变；按钮始终给其标明的球队计分。

旧版本保存的平面／立体偏好不再生效，场地统一使用平面俯视。180° 旋转为本机视图设置，不代表比赛换边，不会改变其他设备的视角；实际半场与自动／手动换边模式属于比赛状态，会同步到同一共享比赛的设备。

球员使用固定示意位置，不支持自由拖动。双打点击任一球员可交换该队两人的固定示意位置；单打位置固定。队内示意换位不会修改球员身份、比分、发球轮次或正式接发顺序，也不代表实时定位或视频追踪。

换边依据 [ITF《2026 网球规则》第 10 条](https://www.itftennis.com/media/7221/2026-rules-of-tennis-english.pdf)：每盘第 1、3 及后续奇数局结束后换边；盘末总局数为奇数时换边，为偶数时不换，待下一盘第 1 局结束后再换；标准抢七每 6 分换边。规则第 14、15 条规定的双打发球及接发轮序与示意站位分别处理，不能通过点击换位改变正式轮序。

上方“换边模式”可切换两种处理方式：

- **自动换边**：新建比赛默认使用。达到规则节点时，在产生该比分的同一次操作中计算并保存半场变化；共享接口将比分、半场、操作回执一起原子提交。撤销该次得分时也会恢复此前半场，重试原请求不会多换一次。
- **手动换边**：保留规则提醒，到达节点后显示“确认换边”，由裁判确认实际换边；非规则节点的人工半场核对需在弹层再次确认。旧存档缺少换边模式字段时继续使用手动模式，不在升级后擅自切换。

手动模式尚有待确认换边时，启用自动模式会先弹层确认；确认后只执行这一次待处理换边，再按后续规则节点自动计算。人工更正比分不会据此猜测实际半场：保留当前半场、清除旧换边提醒并暂停，由裁判结合现场核对半场与发球后继续。

正常同步保持静默，仅以顶部小保存状态标记表示，不会在每次队内换位或计分时弹出等待横幅、成功提示。提交以云端确认结果为准，保存期间暂时阻止重复操作；断网、冲突或长时间未确认时才显示可恢复提示，并保留原请求供重试。

## 嵌入其他工作台

为父容器明确设置高度，iframe 即可填满该容器。建议至少提供横屏 **640 × 360**，或竖屏 **400 × 700** 的可用区域。以下示例不包含房间编号或任何权限密钥：

```html
<div style="width: 100%; height: 720px;">
  <iframe
    src="https://hej014519-web.github.io/tennis-umpire/"
    title="网球裁判工作台"
    style="display: block; width: 100%; height: 100%; border: 0;"
    allowfullscreen
  ></iframe>
</div>
```

示例打开本机工作台；如需加入共享比赛，可在嵌入页面中通过“更多 → 共享比赛”粘贴完整链接。`allowfullscreen` 是可选权限，只用于“更多”中的浏览器全屏功能，填满 iframe 本身不需要它。实际存储、全屏能力仍受宿主页面和浏览器限制。

页面不会强制隐藏微信顶栏，也不会绕过设备的系统旋转锁。外围控件的横竖布局取决于浏览器实际提供的可用视口，球场始终横向显示。

## 多设备使用

1. 打开网站，通过“更多 → 共享比赛”将当前本机比赛创建为共享比赛；已有共享比赛时，可在这里复制现有链接。
2. 将“执裁链接”发到自己的另一台设备，可以继续操作同一场比赛；将“观赛链接”发给观众，只能查看。
3. 其他设备必须打开同一场比赛的完整分享链接。单独发送网站首页不会自动加入某场比赛。

比分、发球、判罚、队内换位、实际半场、换边模式和比赛状态共享保存。旋转视角只调整整个球场的观看方向，比分列与得分按钮在本机跟随场地队伍位置，文字始终正向可读；旋转方向按设备保存，声音由当前页面设置。页面在前台约每 2 秒检查更新；切回页面会重新连接，不承诺零延迟。建议一名主裁操作，其他人用观赛链接。两名裁判同时操作时，先提交成功的一次生效，另一台须核对最新比分后再继续。

共享操作收到服务确认后才更新已确认状态，正常保存仅显示顶部小状态标记。断网或请求结果不明时锁定后续执裁，并保留原请求；使用恢复提示中的重试按钮确认，不会换一个请求编号再次加分。请勿在未确认前清除浏览器数据。这里的链接本身包含访问权限，执裁链接只发给裁判，不要公开张贴。更换浏览器或设备时需要重新打开分享链接。

## 记录与隐私

- 本机模式仅保存在当前设备的浏览器中；创建共享比赛后，比赛记录会存入本项目的 Cloudflare D1 数据库，通过独立共享链接访问。
- 不请求定位，不包含真实赛事报名名单。默认姓名和比赛用于模拟体验。
- 新建比赛会替换当前本机记录；可先通过“导出”保存 JSON 备份。清理浏览器数据或更换浏览器后，本机记录不会自动恢复。
- GitHub Pages 托管静态程序，Cloudflare Worker 提供共享接口。比赛记录、分享密钥和 Cloudflare 账号凭据不会提交到公开源码；数据库只保存分享密钥的哈希。
- 云端未设置比赛自动过期或自动删除。建议定期导出重要比赛记录。免费服务额度耗尽或网络不可达时，同步会暂停并显示错误。

## 本地运行

使用 Node.js 22.13 或更高版本。在项目目录安装依赖后启动：

```sh
npm install
npm run dev
```

检查与生成静态页面：

```sh
npm run test
npm run typecheck
npm run build
npm run preview
```

测试覆盖计分引擎、嵌入式浏览器兼容性、同步客户端和真实隔离 D1 环境中的权限、并发和幂等。构建输出到 `docs/`，同时生成 `docs/.nojekyll`；所有发布资源使用相对路径，适配 GitHub 仓库子路径。依赖版本在 `package.json` 固定；复现安装使用 `npm ci`。

主要目录：`src/` 是静态入口与兼容处理，`components/umpire/` 是裁判界面及互动球场，`lib/` 是计分、存储和同步客户端，`sync-worker/` 是共享接口及数据库迁移，`tests/` 是验证。项目使用 Vite、React、TypeScript 和 Cloudflare Workers/D1。

## 部署共享服务

前端仍发布到 GitHub Pages。部署者需要 Cloudflare 账号，观众和裁判不需要。

```sh
npx wrangler login --scopes account:read user:read workers_scripts:write d1:write pages:write
npx wrangler d1 create startline-tennis-sync --location apac --config sync-worker/wrangler.jsonc
```

将返回的数据库 ID 填入 `sync-worker/wrangler.jsonc` 的 `database_id`，再运行：

```sh
npm run sync:migrate
npx wrangler pages project create startline-tennis-sync --production-branch main
npm run sync:deploy-pages
```

正式共享接口：`https://startline-tennis-sync.pages.dev`。Pages Functions 高级模式复用同一个 Worker 与现有 D1 数据库，只部署接口程序，网页继续由 GitHub 托管。数据库 ID 还须同步到 `sync-worker/pages/wrangler.jsonc`；已有项目更新时直接运行 `npm run sync:deploy-pages`，无需再次创建项目或数据库。

本次自动／手动换边更新同时涉及共享计分引擎和界面：需先更新 Cloudflare Pages 共享接口，再构建并发布 GitHub Pages 前端，不能只替换静态网页。沿用现有 D1 表结构，无需新增数据库迁移；旧比赛和旧存档缺少的新字段按兼容规则读取。

复制 `.env.example` 为 `.env.local`，将 `VITE_SYNC_API_URL` 设置为接口 HTTPS 地址，然后重新检查和构建前端。该地址是公开配置，不能在 `VITE_` 变量中填写账号令牌。留空时仍可使用本机模式。独立 Worker 的可选部署命令保留为 `npm run sync:deploy`；本次网络检查中其默认 `workers.dev` 域名连接超时，因此公开网页采用已验证的 `pages.dev` 地址。

API 提供创建房间、读取房间、原子开赛和命令提交；写入需要独立执裁权限、预期版本和请求编号。D1 事务将版本检查、操作回执和比分一起提交；创建回执可通过原创建密钥恢复。默认只允许本 GitHub Pages 来源和本机开发来源跨域访问。每个网络每小时最多创建 10 场，单次上传上限 1 MiB，房间状态上限 1.5 MB / 5000 条事件。比赛达到上限时会明确拒绝，需导出备份后另建房间。

## 发布到 GitHub Pages

1. 将项目放入 `hej014519-web/tennis-umpire` 仓库，运行检查和 `npm run build`，把源码及生成的 `docs/` 一起提交到 `main` 分支。
2. 打开仓库 **Settings → Pages**，在 **Build and deployment** 中选择 **Deploy from a branch**。
3. 选择 **main** 分支和 **/docs** 目录，点击 **Save**，等待 GitHub 显示发布结果。
4. 打开上述 `github.io` 地址验证。后续更新重新构建并提交 `docs/` 即可。

如果仓库名称改变，请同步更新本页地址和 `index.html` 的 `og:url`。可以把发布地址发送到微信中打开；微信内的网络可达性、全屏支持和链接卡片展示取决于微信及网络环境，需在实际设备验证。
